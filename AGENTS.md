# AGENTS.md

## Build and verification

- Treat `go.mod` and `web/package.json` as authoritative; the root README contains stale tool versions and frontend build paths.
- Go commands require Go 1.26 and the sibling module resolved by `replace github.com/looplj/axonhub/llm => ../axonhub/llm`. From this checkout, that path is `/opt/ocode/axonhub/llm`.
- Install frontend dependencies with `cd web && pnpm install --frozen-lockfile`.
- Routine frontend checks: `cd web && pnpm lint && pnpm build`. The build runs `tsc --noEmit` before Vite and writes directly to `static/out`.
- After frontend build, routine backend checks are `go test ./...` and `go build ./...`. There are currently no repository test files, so `go test` is principally a compile/package check.
- Start the backend with `go run . start`; configuration defaults to ignored local state at `data/config.json`. Override it with `--config <path>` or `OCTOPUS_*` variables; dots map to underscores and `OCTOPUS_DEBUG=true` enables debug behavior.
- For frontend development, start the backend first, then run `cd web && VITE_PROXY_TARGET=http://127.0.0.1:8080 pnpm dev`. Vite defaults to port 5173 and proxies `/api`; `DISABLE_HMR=true` disables HMR/watch.
- `bash scripts/build.sh help` is the packaging command reference. `bash scripts/build.sh build <os> <arch>` builds one target; `bash scripts/build.sh release` builds release artifacts under `build/`.
- Do not use the packaging script as a routine check: it installs dependencies, runs `go mod tidy`, refreshes price presets from the network, builds the frontend, and can modify tracked files.
- CI has release automation but no pull-request verification gate; run the relevant checks locally.

## Architecture and boundaries

- `main.go` enters Cobra in `cmd/`; `cmd/start.go` initializes config, logging, shutdown, database, caches, default user, HTTP server, and scheduled tasks.
- `internal/server/handlers` owns management HTTP binding/auth/responses; `internal/op` owns database and cache operations; `internal/model` owns persistence and request types; `internal/task` owns scheduled jobs.
- Management handlers self-register in `init()` through `router.NewGroupRouter`; `internal/server/server.go` blank-imports the handlers package and calls `router.RegisterAll`. Preserve this side-effect wiring when adding routes.
- Relay `/v1/*` routes are wired directly in `internal/server/server.go`. `internal/relay` owns channel selection, balancing, forwarding, metrics, and persistence integration.
- Protocol parsing/transformation belongs in the sibling `axonhub/llm` module or thin Octopus adapters. Do not duplicate protocol conversion policy in handlers or channel selection code.
- Database startup runs registered before-migrations, GORM `AutoMigrate`, then after-migrations. Put historical schema/data transformations in the next versioned `internal/db/migrate/NNN.go`, register them via `init()`, and account for SQLite, MySQL, and PostgreSQL.
- Frontend entry is `web/src/main.tsx`; application bootstrap/shell is in `web/src/components/app.tsx`; lazy page mapping is in `web/src/route/config.tsx`; API calls and types belong in `web/src/api`.
- Frontend imports may use `@/*` for `web/src/*`. Keep API URLs same-origin; Vite's proxy handles local backend routing.

## Generated and stateful files

- `static/static.go` embeds `static/out`. Build the frontend before a production Go binary or embedded-UI check.
- Vite empties and rewrites `static/out`; generated assets there are ignored except `static/out/README.md`. Do not commit them or move a nonexistent `web/out` directory.
- `internal/price/presets.go` is generated by `scripts/updatePrice.py` from `https://models.dev/api.json`. Do not edit it manually; regenerate only for an intentional pricing refresh and review the diff.
- `data/` and `build/` are local runtime/build state. Avoid committing generated databases, configs, binaries, archives, or Docker build output.
- Stop runtime QA gracefully rather than using `SIGKILL`: shutdown flushes statistics, channel-key state, and relay logs from caches.

## Workflow

- Keep each pull request to one change topic, as required by `CONTRIBUTING.md`.
- Human-review all AI-assisted changes before submission.
- Release automation treats `dev` as the development branch and merges it into `master` during the `v*` tag changelog workflow; do not casually reproduce its force-push behavior locally.
